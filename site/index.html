// dependabot for api breakage

A dependency upgrade turned your build red. Get it back to green, as a PR.

Dependabot tells you a version changed. It doesn't fix your code when the change is breaking. That part is still yours: read the changelog, find the moved API, patch every call site, re-run. This does that part for you.

Get it on GitHub See the one-liner
self-maintain upgrade . @acme/sdk
self-maintain upgrade . @acme/sdk
▶ bump   @acme/sdk → 2.0.0
▶ build  tsc --noEmit
  app.ts(7,9): error TS2554: Expected 2 arguments, but got 1.
✗ red · fix round 1/3

▶ patch  app.ts   // v2: send(options) → send(channel, msg)
  -  await send({ channel: "alerts", message: "build failed" });
  +  await send("alerts", "build failed");

✓ green · commit + push
✓ PR opened  →  chore(deps): bump @acme/sdk to latest

how it works

01

Bump, then run your build

On a fresh branch it bumps the dependency to latest and runs the cheapest check you have that the API still fits: your typecheck first, then your build script.

02

Migrate the call sites

If the build breaks, the exact errors and the files they name go to Claude with a tight "migrate only, don't refactor" brief. It writes the patched files back, re-runs the build, and loops, up to three rounds.

03

Ship a green PR, or step back

Green, and it opens the PR with a summary of what broke and what changed. Still red after three rounds, and it stops and leaves the branch. It never pushes a half-migration.

the wedge

Dependabot keeps your versions current. It hands you the breakage.

And that breakage is the same shape every time: read the changelog, find the moved API, patch the call sites, re-run. That work is a good fit for an agent, and you can point it at every repo you already maintain.

use it

# one-off, locally
npx self-maintaining-apis upgrade . @acme/sdk

# or in CI: a GitHub Action opens the PR for you
- uses: snenenenenenene/self-maintaining-apis@v1
  with:
    dependency: @acme/sdk
    anthropic-api-key: ${{ secrets.ANTHROPIC_API_KEY }}

No Claude Code install and no interactive login. The fix step calls the Anthropic API directly, so it runs unattended in CI. A clean bump gives you a boring PR. If it can't fix the break in three rounds, it stops and leaves the branch for a human.
