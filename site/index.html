Dependabot for API breakage

A dependency upgrade broke your build. Get a green PR, not a red one.

Dependabot tells you a version changed. It doesn't fix your code when the change is breaking — that's still a human afternoon of reading changelogs and chasing type errors. This closes that last mile.

Get it on GitHub → See the one-liner
self-maintain upgrade . @acme/sdk
1 · the upgrade breaks the build
▶ bump: @acme/sdk → 2.0.0 ▶ build: tsc --noEmit app.ts(7,9): error TS2554: Expected 2 arguments, but got 1.   ✗ build red — fix round 1/3 ▶ asking Claude to patch 1 file…
2 · the agent migrates the call site
// v2: send(options) → send(channel, msg) - await send({ channel: "alerts", - message: "build failed" }); + await send("alerts", "build failed");   ✓ build green after 1 fix round ✓ PR opened →

How it works

01

Bump & run

On a fresh branch it bumps the dependency to latest and runs your build — the cheapest "does the API still fit" check you have (typecheck, then build).

02

Migrate & verify

If it breaks, the exact errors and your call sites go to Claude with a tight "migrate only, don't refactor" brief. It patches, re-runs, and loops — bounded to 3 rounds.

03

Ship or step back

Green → it opens the PR with a summary of what broke and what changed. Still red after 3 rounds → it stops and leaves the branch. No half-migrations pushed silently.

Why this is the wedge

Dependabot and Renovate keep your versions current but hand you the breakage. The fix is still manual — and it's the same shape every time: read the changelog, find the moved API, patch the call sites, re-run. That last mile is exactly what an agent is good at, and it's dogfoodable across every repo you already maintain.

Use it

# one-off, locally
npx self-maintaining-apis upgrade . @acme/sdk

# or in CI — a GitHub Action opens the PR for you
- uses: snenenenenenene/self-maintaining-apis@v1
  with:
    dependency: @acme/sdk
    anthropic-api-key: ${{ secrets.ANTHROPIC_API_KEY }}

No Claude Code install and no interactive login — the fix step calls the Anthropic API directly, so it runs unattended in CI. Clean bump → boring PR. Can't fix it in three rounds → it stops and leaves the branch for a human.
